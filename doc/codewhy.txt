1. INTRODUCTION                                                 *codewhy-intro*

Select code, press a key, and get an explanation streamed into a floating
chat panel beside your code. codewhy asks your language server for the
definitions of the symbols in the selection and the places they're used, adds
any diagnostics on those lines, and sends that context along with the code.
Follow-up questions continue the conversation.

Requires Neovim 0.10+ and curl 7.76+. Run |:checkhealth| codewhy to verify.

==============================================================================
2. SETUP                                                        *codewhy-setup*

With lazy.nvim: >lua
    {
      "bob4202/codewhy.nvim",
      opts = {},
    }
<
Without a plugin manager, call `require("codewhy").setup({})`.

On first use you're asked to pick a model (free models are listed first) and,
if no key is configured, to enter your OpenRouter API key, which is saved to
the system keyring.

==============================================================================
3. COMMANDS                                                  *codewhy-commands*

                                                                     *:CodeWhy*
:[range]CodeWhy explain       Explain the selection, range, or current line.
                              Default mapping: <leader>ce (normal and visual).

:[range]CodeWhy diagnostic    Explain the errors/warnings on these lines and
                              how to fix them. Default mapping: <leader>cd.

:[range]CodeWhy ask [question]
                              Ask your own question about the code. Without
                              a question, attaches the code to the message
                              box (shown as @file:lines) for you to type it.
                              Default mapping: <leader>ca.

:CodeWhy toggle               Show or hide the chat panel. After a restart it
                              reopens the most recent chat.
                              Default mapping: <leader>cc.

:CodeWhy chat [question]      Send a message in the current chat, or focus
                              the message box if no question is given.

:CodeWhy new                  Start a new chat. Default mapping: <leader>cn.

:CodeWhy history              Reopen a saved chat. Default mapping: <leader>ch.

:CodeWhy history delete       Pick a saved chat and delete it.

:CodeWhy history clear        Delete every saved chat (asks first).

:CodeWhy delete               Delete the open chat (asks first).

:CodeWhy stop                 Stop the answer being streamed.

:CodeWhy model [free]         Pick a model from the provider's live list.
                              The choice is remembered across sessions.

:CodeWhy key [delete]         Save the API key to the system keyring, or
                              remove it.

==============================================================================
4. CHAT PANEL                                                   *codewhy-panel*

Answers go to a chat panel, a split on the right by default (`ui.layout =
"float"` for a centered window instead), with a message box docked under it
that stays open so you can keep chatting. Each explain/ask adds a turn to the
current chat, and the whole conversation is sent with every message, so you
can ask "why?" about the previous answer. Your cursor stays in the code while
an explanation streams in. Only one answer streams at a time.

In the message box:
    <CR>        Send. The box clears and stays focused for the next one.
    <C-j>       New line.
    <C-x>       Remove the attached code (see |:CodeWhy| ask).
    <C-c>       Stop the answer.

In the chat area:
    i, a, <CR>  Jump to the message box.
    n           New chat.
    H           Chat history.
    D           Delete this chat (asks first).
    y           Yank the last answer to the unnamed and `+` registers.
    p           Show exactly what was last sent to the model.
    <C-c>       Stop the answer.
    q           Hide the panel. The chat, any answer still streaming, and a
                half-written message are kept.

                                                              *codewhy-history*
Finished turns are saved to `stdpath("data")/codewhy/sessions/` as JSON, in a
0700 directory with 0600 files, since they contain the code that was sent.
The newest `history.max_sessions` are kept. Delete chats with `D` in the
panel, |:CodeWhy| history delete, or |:CodeWhy| history clear. Long chats are trimmed to the
newest `history.max_chars` characters when sent. Set `history.enabled = false`
to keep chats in memory only.

                                                               *codewhy-render*
The chat is rendered as a reading view: headings lose their `#`s and get a
tinted band, lists get bullets and checkboxes, code blocks are shaded with a
language label, tables are drawn with box characters and re-aligned, and `---`
becomes a full-width rule. The buffer text stays plain markdown, so `y` yanks
markdown. Colors are blended from your colorscheme and follow |:colorscheme|.

Set `ui.render` to `"builtin"` to always use this, or `false` for plain
markdown. The default, `"auto"`, steps aside if render-markdown.nvim or
markview.nvim is loaded, since those already render markdown buffers.

Highlight groups, all overridable: CodewhyH1..CodewhyH6, CodewhyH1Bg..
CodewhyH6Bg, CodewhyCode, CodewhyInlineCode, CodewhyCodeLabel, CodewhyBullet,
CodewhyUnchecked, CodewhyChecked, CodewhyQuote, CodewhyRule, CodewhyTable,
CodewhyTableHeader.

5. API KEY                                                    *codewhy-api-key*

The key is looked up in this order:

  1. `api_key_cmd`: a list (argv) or a string (run with `sh -c`). The first
     line of its stdout is used. >lua
         api_key_cmd = { "pass", "show", "openrouter" }
         api_key_cmd = "gpg -dq ~/.secrets/openrouter.gpg"
<
  2. The environment variable named by `api_key_env` (`OPENROUTER_API_KEY`).
  3. The system keyring via `secret-tool` (see |:CodeWhy| key).

A plain `api_key = "..."` option is deliberately not supported. The key is
kept in memory only, never logged, and passed to curl on stdin so it does not
appear in the process list.

6. CONFIGURATION                                               *codewhy-config*

Defaults: >lua
    require("codewhy").setup({
      provider = "openrouter",
      model = nil,
      api_key_cmd = nil,
      api_key_env = "OPENROUTER_API_KEY",
      keymaps = {          -- set any to false to disable
        explain = "<leader>ce",
        diagnostic = "<leader>cd",
        ask = "<leader>ca",
        toggle = "<leader>cc",
        new = "<leader>cn",
        history = "<leader>ch",
      },
      context = {
        lsp = true,
        lsp_timeout_ms = 2000,
        max_symbols = 15,
        max_snippets = 8,
        max_snippet_lines = 60,
        max_references = 5,
        surrounding_lines = 20,
        max_chars = 30000,
        project_only = true,
        exclude = { "/node_modules/", "/.venv/", "/venv/", "/site-packages/",
                    "/vendor/", "/.git/", "/.env", ".pem", "/id_rsa",
                    "/id_ed25519", "/.ssh/" },
      },
      ui = {
        layout = "panel",  -- or "float"
        panel = { position = "right", width = 0.35, focus = false },
        width = 0.6,       -- float size
        height = 0.6,
        border = "rounded",
        render = "auto",   -- "auto" | "builtin" | false, see |codewhy-render|
      },
      history = { enabled = true, max_sessions = 50, max_chars = 60000 },
      providers = {
        openrouter = {
          base_url = "https://openrouter.ai/api/v1",
          temperature = 0.2,
          max_tokens = nil,
          timeout = 180,
        },
      },
    })
<
`context.exclude` entries are plain substrings of the file path. Setting it
replaces the default list.

==============================================================================
7. WHAT GETS SENT                                             *codewhy-privacy*

Only: formatting instructions (including the panel's width, so answers avoid
tables and long lines that would wrap), the selected lines,
`surrounding_lines` above and below, diagnostics on the selection, the enclosing definitions of symbols used in the selection, and
a few lines around usages of the main symbol.

With `project_only = true`, files outside the working directory are never
sent. Symlinks are resolved first, so a link inside the project cannot pull in
a file from elsewhere. Press `p` in the chat panel to see the exact prompt.

==============================================================================
8. ADDING A PROVIDER                                        *codewhy-providers*

Create `lua/codewhy/providers/<name>.lua` returning a table with:

  stream(req, handlers) -> { cancel = fun() }
      req      = { model, messages, api_key, options }
      handlers = { on_chunk(text), on_reasoning(text)?, on_done(),
                   on_error(msg) }

  list_models(options, cb)
      cb(models | nil, err | nil), each model being
      { id, name, free, context_length, prompt_price, completion_price }

Then set `provider = "<name>"` and add its options under `providers.<name>`.
